# Phase 0：レシート読み取り精度の検証

コードは書かず、Google AI Studio の画面で Gemini にレシート画像を読ませて精度を確かめる。
結果をもとに、Phase 4 で使うモデルと、送信前の画像の扱い（トリミング・縮小）を決める。

> **このファイルに個人の家計データを書かない。**
> レシート画像と、レシートごとの結果の表はリポジトリに入れない。ここに書くのは手順・指示文・集計した数字だけにする。

## 前提（2026-10-14 時点で公式情報を確認）

- 料金：無料枠の対象に Gemini 3.8 Flash／3.5 Flash-Lite が含まれる。無料枠では、送った内容が製品改善に使われる。Google AI Studio の利用は無料。
  https://ai.google.dev/gemini-api/docs/pricing
- 規約：AI Studio の画面での利用も無料枠（Unpaid Services）の扱いになる。送った内容は人間が確認する場合があり、個人情報を送らないよう求められている。
  https://ai.google.dev/gemini-api/terms
- 1日あたりの上限はモデルごとに違い、AI Studio の画面で確認する。
  https://ai.google.dev/gemini-api/docs/rate-limits
- 日本は利用可能な地域に含まれる。
  https://ai.google.dev/gemini-api/docs/available-regions

## 比較するモデル

| 略称 | モデル | 選んだ理由 |
|---|---|---|
| A | Gemini 3.5 Flash-Lite | 軽量版の最新 |
| B | Gemini 3.8 Flash | Flash の最新 |

当初は C として Gemini 2.5 Flash も比べる予定だったが、2.5 系は過去に使ったことのある利用者しか使えないよう制限されていたため外した（廃止ではない。https://ai.google.dev/gemini-api/docs/models 、2026-10-15 確認）。

AI Studio に表示されるモデル名（ID）は、結果の記録に控えておく（Phase 4 でスクリプトプロパティ `GEMINI_MODEL` に入れる値になる）。

## 手順

### 1. レシートを用意する（5枚）

枚数が少ないので、種類はなるべくばらけさせる。例：

- スーパーの長いレシート、コンビニ、ドラッグストア、飲食店
- クレジットカードの控え
- 割引・ポイント利用・外税の行があるもの
- インクが薄れたもの、しわのあるもの
- 斜めに撮ったもの、暗い場所で撮ったもの

普段使う想定どおり、iPhone のカメラで撮る。

### 2. 個人情報を除く（送る前に必ず）

写真アプリの切り取り（トリミング）で、次の部分を画像から除く。
カード番号（下4桁を含む）、会員番号、ポイントカード番号、氏名、電話番号、バーコード、QRコード。

除いた部分は「どの位置にあったか」をメモしておく（Phase 4 でトリミングの方針を決める材料になる）。

### 3. 判定のつけ方

正解と出力を書き写す必要はない。レシートとモデルの出力をその場で見比べ、項目ごとに ○／△／× だけを結果の表（後述）に記入する。
× や △ のときは、どう間違えたかを備考に一言書く（例：小計を合計と取り違えた、和暦を変換できなかった）。金額や店名そのものは書かない。

### 4. AI Studio で読ませる

1. https://aistudio.google.com を開き、新しいプロンプト（チャット）を作る
2. 右側の設定でモデルを A に切り替える
3. 画像を添付し、下の「指示文」を貼り付けて実行する
4. 出力をレシートと見比べ、項目ごとに ○／△／× を表に記入する
5. モデルを B に切り替えて、同じ画像・同じ指示文で繰り返す

- 設定の「温度（Temperature）」などは既定値のまま、すべてのモデルで同じにする。
- 設定に構造化出力（Structured output / JSON schema）を指定する欄があれば、下の「出力の形」を貼ってもよい。AI Studio の画面でスキーマを指定できるかは未確認。指定しなくても、指示文だけで JSON が返るかを見る。
- 画面の項目名は変わりやすいので、上の操作名は目安。

### 5. 縮小の影響を見る（1枚）

No.1 のレシートの写真を全画面表示してスクリーンショットを撮り、解像度を下げた画像でも試す。
元の写真と結果が変わるかを比べる（スクリーンショットで縮小の代わりになるかは推論）。

### 6. 上限を控える

AI Studio の利用上限のページ（https://aistudio.google.com/rate-limit ）で、A・B それぞれの「1日あたりのリクエスト数」を控える。

## 指示文（すべてのモデルで共通）

```
あなたは日本のレシートを読み取るアシスタントです。
添付のレシート画像から次の項目を読み取り、JSON だけを出力してください。説明文やコードブロックの記号（```）は付けないでください。

- date: 支払日。YYYY-MM-DD 形式。和暦は西暦に直す。読めなければ null
- store: 店名。支店名があれば含める。読めなければ null
- total: レシートの「合計」欄の税込金額（円、整数）。お預かり・お釣りの金額ではない。読めなければ null
- items: 明細の配列。各要素は {"name": 商品名, "price": 金額（円、整数）}。値引きの行は price を負の数にする。読めなければ空の配列
- payment: 支払方法。次のどれか1つ：現金、クレジットカード、電子マネー、QRコード決済、口座振替・振込。判断できなければ null

推測で値を作らないでください。読めない項目、写っていない項目は null にしてください。
カード番号、会員番号、氏名などの個人情報は出力しないでください。
```

`payment` の選択肢は、アプリの選択肢（`docs/js/options.js`）に合わせている。

## 出力の形（構造化出力を指定できる場合のみ）

```json
{
  "type": "object",
  "properties": {
    "date": { "type": ["string", "null"], "description": "支払日 YYYY-MM-DD" },
    "store": { "type": ["string", "null"] },
    "total": { "type": ["integer", "null"], "description": "合計（税込、円）" },
    "items": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "name": { "type": "string" },
          "price": { "type": "integer" }
        },
        "required": ["name", "price"]
      }
    },
    "payment": {
      "type": ["string", "null"],
      "enum": ["現金", "クレジットカード", "電子マネー", "QRコード決済", "口座振替・振込", null]
    }
  },
  "required": ["date", "store", "total", "items", "payment"]
}
```

`null` を許す書き方（`"type": ["string", "null"]`）を AI Studio が受け付けるかは未確認。エラーになる場合は構造化出力を使わず、指示文だけで試す。

## 結果の表（個人用。リポジトリに入れない）

Google スプレッドシートなどに、次の列で作る（家計データ用の `transactions` とは別のファイルにする）。
1枚のレシート × 1つのモデルで1行。必須なのは種類・各判定・JSONで返ったか・備考で、正解・出力・明細・所要時間の列は任意。

```
No,種類,画像,モデル,date正解,date出力,date判定,store正解,store出力,store判定,total正解,total出力,total判定,payment正解,payment出力,payment判定,明細数正解,明細一致数,JSONで返ったか,所要時間(秒・目安),備考
```

- 種類：スーパー／コンビニ／飲食店 など
- 画像：元 または 縮小
- 判定：○（一致）、△（店名の表記ゆれなど、どの店か分かる）、×（誤り・null）
- 明細一致数（任意）：商品名がおおむね合っていて、金額が正しい行の数

## 判断の基準

確認・修正画面が必ずあるので、完璧でなくてよい。元の画像での結果を目安に判断する。

| 項目 | 基準（5枚中） |
|---|---|
| total | 4枚以上で ○ |
| date | 4枚以上で ○ |
| store | 4枚以上で ○ か △ |
| payment、明細 | 参考として記録する |

基準を満たすモデルのうち、軽く、1日の上限に余裕があるものを採用候補にする。

## 結果のまとめ（2026-10-15 実施）

| 項目 | A: 3.5 Flash-Lite | B: 3.8 Flash |
|---|---|---|
| AI Studio 上のモデル名（ID） | `gemini-3.5-flash-lite` | `gemini-3.8-flash` |
| 1日あたりの上限（リクエスト数） | 未確認 | 未確認 |
| total ○ の数 / 枚数 | 5 / 5 | 5 / 5 |
| date ○ の数 / 枚数 | 5 / 5 | 5 / 5 |
| store ○△ の数 / 枚数 | 5 / 5 | 5 / 5 |
| payment ○ の数 / 枚数 | 5 / 5 | 5 / 5 |
| 明細の一致率（一致行 / 全行） | 記録せず | 記録せず |
| JSON で返った数 / 枚数 | 5 / 5 | 5 / 5 |
| 所要時間の平均（秒） | 6.4 | 9.5 |
| 縮小画像での変化（1枚） | なし（total・date・store とも ○） | なし（同左） |

- 1日あたりの上限：公式ドキュメントに無料枠の数値はなく、AI Studio の利用上限のページ（ログインが必要）でしか確認できない。上限はプロジェクト単位で、1日の回数は太平洋時間の0時にリセットされる（https://ai.google.dev/gemini-api/docs/rate-limits 、2026-10-13 更新）。
- 結果の限界：5枚での検証なので、偶然うまくいった可能性は残る。縮小画像は1枚、明細は記録していない。実際の精度は Phase 4 で確認画面を通して見ていく。

## 決定事項

- 読み取り方式：Gemini（Google AI Studio と同じモデルを、GAS から Gemini API で呼び出す）
- 採用モデル：`gemini-3.5-flash-lite`。精度は B と同じで、速く、軽量版のため。読み取りの失敗が増えたら `gemini-3.8-flash` に切り替える（スクリプトプロパティ `GEMINI_MODEL` の書き換えだけで済む）。
- 送信前のトリミング：個人情報（カード番号・会員番号・氏名・電話番号・バーコードなど）の部分を除いてから送る方針を維持する。方法（アプリ内の切り取り画面か、写真アプリで切り取ってから選ぶ運用か）は Phase 4 で決める。
- 送信前の縮小：縮小する。スクリーンショット程度の解像度でも読めた（1枚での結果）。縮小後の大きさは Phase 4 で決める。
